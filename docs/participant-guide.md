# 参加者ガイド — GitHub Copilot × 簡略化 SDD ワークショップ

このガイドは、ワークショップ当日に手元で参照する詳細手順です。講師の説明と合わせて読み進めてください。

## 0. このワークショップについて

- GitHub Copilot の基本操作を学んだ上で、「雑な要望 → 要件定義書 → 設計書 → ワイヤーフレーム」という簡略化した SDD（Spec Driven Development）ライフサイクルをハンズオンで体験します。
- 各ステップは専用のカスタムエージェント（`sdd-requirements` / `sdd-design` / `sdd-wireframe`）が担当します。
- 全体の時間割は [workshop-timetable.md](workshop-timetable.md) を参照してください。

## 2. GitHub Copilot 画面操作クイックリファレンス

### チャットの開き方

| 操作 | ショートカット |
|---|---|
| サイドバーチャット | `Ctrl+Alt+I`（Mac: `Ctrl+Cmd+I`） |
| インラインチャット | `Ctrl+I`（Mac: `Cmd+I`） |

### 3 つのモード

| モード | 動作 | 使う場面 |
|---|---|---|
| **Agent**（デフォルト） | ファイル編集＋ターミナル実行 | 本ワークショップのハンズオンは基本 Agent モードを使用 |
| **Ask** | 質問に回答するだけ | 用語や仕組みの確認 |
| **Plan** | 計画を立ててから実装 | 大きな変更を始める前の確認 |

### モデル選択

- チャット入力欄のモデル名をクリックして切り替え可能。
- 迷ったらバランス型のモデル（例: Claude Sonnet 系）から始めてください。

## 3. コンテキストの与え方

Copilot への回答品質は「何を見せるか」で決まります。

| 操作 | 効果 |
|---|---|
| `#file:ファイル名` | 特定ファイルを参照させる |
| `#folder:フォルダ名` | フォルダ配下を参照させる |
| `@workspace` | ワークスペース全体を検索対象にする |
| ドラッグ＆ドロップ | 画像・ファイルを直接添付する |
| URL を貼る | Web ページの内容を参照させる |

> ハンズオンでは主に `#file:` を使って、議事録・要件一覧・設計書をエージェントに渡します。

## 4. Instruction / Skill / Agent の基礎

| 仕組み | ファイル | 役割 |
|---|---|---|
| **Instruction** | `.github/copilot-instructions.md` など | リポジトリ全体に常に適用するルール |
| **Skill** | `.github/skills/*/SKILL.md` | ドメイン知識・手順を自動マッチで提供 |
| **Agent** | `.github/agents/*.agent.md` | `@agent名` で明示的に呼び出す役割特化のエージェント |

本リポジトリの `.github/agents/` には、ハンズオンで使う 3 つのエージェントが定義されています。

## 5. エージェントの呼び出し方（チャットへの入力方法）

カスタムエージェント（`sdd-requirements` / `sdd-design` / `sdd-wireframe`）は、チャット入力欄から次の 2 通りの方法で呼び出せます。

### 方法①: `@エージェント名` を先頭に入力する（本ガイドではこちらを使用）

チャット入力欄にそのまま `@` に続けてエージェント名を入力し、続けて依頼内容や `#file:` によるファイル参照を書きます。

```
@sdd-requirements #file:samples/meeting-notes-sample.md をもとに要件一覧を作成してください。
```

- `@` を入力すると候補一覧が表示されるので、そこから `sdd-requirements` などを選ぶと入力ミスを防げます。
- 1 つのメッセージ内で完結し、モードを元に戻す必要はありません。

### 方法②: モード選択ドロップダウンからエージェントに切り替える

1. チャット入力欄の下部にある、現在のモード（既定では「Agent」）を表示しているドロップダウンをクリックする。
2. 一覧から `sdd-requirements` などのエージェント名を選択する。
3. 選択後は、以降に送信するメッセージがすべてそのエージェントとして実行される（`@エージェント名` を毎回入力する必要はない）。
4. 別のエージェントや通常の Agent モードに戻したい場合は、同じドロップダウンから選び直す。

> 複数のメッセージを同じエージェントで連続してやり取りする場合は方法②が、1 回だけ別のエージェントに頼みたい場合は方法①が便利です。困ったら講師に確認してください。

## 6. ハンズオン手順: 簡略化 SDD ライフサイクル

### ステップ①: 要件一覧を作る（`sdd-requirements`）

1. VS Code のチャットを開き、Agent モードであることを確認する。
2. サンプル議事録を渡して要件一覧の作成を依頼する。

   ```
   @sdd-requirements #file:samples/meeting-notes-sample.md をもとに要件一覧を作成してください。
   ```

3. 生成された `work/requirements.md` を確認する。運用・開発・営業の視点で抜け漏れがないか、Copilot とのやり取りで深掘りしてみる。
4. 自分たちの会社の要望に置き換えて、自由記述でも試してみる（例: `@sdd-requirements 我が社でも問い合わせ対応を自動化したい`）。

### ステップ②: 設計書を作る（`sdd-design`）

1. ステップ①で作成した `work/requirements.md` を入力にする。

   ```
   @sdd-design #file:work/requirements.md をもとに設計書を作成してください。
   ```

2. 生成された `work/design.md` を確認する。要件のどの項目が設計のどの部分に対応しているか、対応関係を意識して読む。

### ステップ③: ワイヤーフレームを作る（`sdd-wireframe`）

1. ステップ②で作成した `work/design.md` を入力にする。

   ```
   @sdd-wireframe #file:work/design.md をもとにワイヤーフレーム（HTML）を生成してください。
   ```

2. 生成された `work/wireframe.html` を VS Code のプレビューやブラウザで開いて確認する。

## 7. トラブルシューティング

| 事象 | 対処 |
|---|---|
| Copilot アイコンに警告マークが出る | ライセンスまたはネットワークの問題の可能性。講師に相談してください。 |
| `@sdd-requirements` などが候補に出てこない | ワークスペースが本リポジトリのルートで開かれているか確認してください（`.github/agents/` を認識させるため）。 |
| 生成結果が期待と違う | 一度に完璧を求めず、「ここをもっと詳しく」「〇〇の観点が抜けている」と追加で依頼してみてください。 |
| `work/` に前回の成果物が残っている | 上書きしてよいか確認しながら進めるか、ファイル名を変えて保存してください。 |
